Help & Testing Guide

Documentation, rules, safeguards, and testing instructions for this academic assignment.

⚠ Fictional Demo Data Notice
All member names, companies, roles, and activity records in this application are entirely fictional. They are created for academic demonstration purposes only and do not represent real people, real Friends of Finance members, or actual community activity. Commercial intent must not be inferred from community activity.

1. Purpose of this CRM

This is an academic assignment project: a CRM-style dashboard designed for a fictional community manager to track and manage member activity in Friends of Finance — a professional community for finance and accounting practitioners.

The CRM allows a community manager to:

  • View a community overview dashboard with key performance indicators
  • View, add, and edit fictional member records
  • Record member activities in relevant community spaces
  • Automatically classify members by activity state
  • Identify members needing follow-up attention
  • Use simulated AI-assisted next-step suggestions (with mandatory human review)

2. Technology Used

  • Frontend: HTML5, CSS3, Vanilla JavaScript
  • Backend: Node.js + Express.js
  • Database: MongoDB + Mongoose
  • Charts: Chart.js (CDN)
  • Fonts: Google Fonts — Inter
  • Hosting: Deployable to Render (or similar)

3. Fictional Data Disclaimer

All member names, companies, roles, email addresses, and activity descriptions in this application are entirely fictional and created solely for academic demonstration purposes.

Specifically:

  • No real people's information is used.
  • No real Friends of Finance members are represented.

  • Commercial intent must not be inferred from any community activity shown.

4. Activity State Rules

The following CRM rules were created specifically for this assignment. They are not claimed to be official Friends of Finance activity classification rules. All states are calculated automatically from the member's joined date and activity history. Commercial signals are never used in state calculations.

State Rule Badge
Newly Joined Member joined within the last 7 days 🔵 Newly Joined
Highly Active 5 or more meaningful activities in the last 14 days 🟣 Highly Active
Active 2 to 4 meaningful activities in the last 14 days 🟢 Active
At Risk No meaningful activity for 15 to 30 days 🟠 At Risk
Dormant No meaningful activity for more than 30 days 🔴 Dormant

Note: "Newly Joined" takes priority over all other states. Activity state is computed dynamically on every request.

6. AI Feature Explanation

The AI Suggested Next Step feature on the Member Detail page generates a suggested action for the community manager to consider.

How it works

This AI feature is fully simulated for this assignment using rule-based JavaScript logic. It does not call any paid external AI API. The suggestion is generated by analysing:

  • The member's current activity state
  • Their most active community space
  • Their recent activity types (questions, posts, etc.)
  • Their role and engagement history

Example outputs

  • Newly Joined → Suggest a welcome/check-in action
  • Highly Active → Acknowledge contributions; invite to discussions
  • Active, asks questions → Suggest relevant peer resources
  • At Risk → Recommend reviewing history before any outreach
  • Dormant → Recommend careful human review before any action

7. AI Safeguards

The AI feature includes the following mandatory safeguards displayed on every recommendation:
  • ✓ AI recommendation is simulated for this assignment. It uses rule-based logic, not a paid AI API.
  • ✓ AI does not send messages automatically. Human review is always required.
  • ✓ AI does not invent personalisation or access external data.
  • ✓ Community activity must NOT be treated as commercial intent.
  • ✓ AI does not infer buying intent. No member is labelled as a sales lead.

The AI will never say: "This member is likely to buy", "This member is a sales lead", or make any commercial inference.

8. Commercial Signal Safeguards

The Commercial Signal field is an optional field with two possible values: Not assessed (default) and Requires human review.

This field is:

  • Completely separate from activity scoring
  • Not used in activity state calculation
  • Not used in engagement ranking
  • Not used in AI suggestion generation
  • Clearly displayed as separate from community engagement

Community engagement and commercial assessment are treated as entirely separate concerns in this CRM.

9. Testing Instructions

Use the following tests to verify all CRM features work correctly. All tests should be performed with the fictional demo data.

Test 1 — Add a New Member

Go to Members → Add Member. Fill in name, role, company, email, and set today's date as the joined date. Submit the form.

Expected: Member appears in the Members table. Activity state is "Newly Joined" because joined date is within 7 days.
Test 2 — Become Highly Active

View any member. Click Add Activity and add 5 activities, all with dates within the last 14 days.

Expected: Member's activity state updates to "Highly Active" after adding the 5th recent activity.
Test 3 — Become Active

View a member. Add exactly 2 activities with dates within the last 14 days.

Expected: Member's activity state becomes "Active" (2–4 activities in 14 days).
Test 4 — At Risk Classification

Check a member such as Rahul Mehta or Meera Krishnan in the seed data. Their most recent activity is 15–30 days ago.

Expected: Member shows "At Risk" state in the Members table and the At Risk focused view.
Test 5 — Dormant Classification

Check a member such as Arjun Shah or Neha Iyer in the seed data. Their most recent activity is over 30 days ago.

Expected: Member shows "Dormant" state and appears in Dormant focused view and Follow-ups.
Test 6 — Search Members

Go to Members. Type a name (e.g. "Ananya") in the search box.

Expected: Only Ananya Rao appears in the results. Other members are filtered out.
Test 7 — Filter by Activity State

Go to Members. Select "Highly Active" from the Activity State filter dropdown.

Expected: Only members with "Highly Active" state are displayed in the table.
Test 8 — Add an Activity

View any member. Click Add Activity. Fill in all fields and submit.

Expected: Activity appears in the member's history. Last activity date updates. Activity state may recalculate.
Test 9 — AI Recommendation

View any member's detail page. Scroll to the AI Suggested Next Step section and click the button.

Expected: A recommendation is displayed. It is clearly marked as simulated and requires human review. No commercial intent is inferred.
